# Prompt Atelier — 技术决策与经验

## 已确认决策
| 主题 | 决策 |
|---|---|
| 产品定位 | AI 服装视觉资产与提示词智能生产工作台 |
| 用户 | 当前个人使用，未来考虑团队协作 |
| AI 分析 | AI API + 本地程序；结果人工确认 |
| 采集来源 | 指定本地文件夹自动扫描，不限定平台 |
| 数据保存 | 默认全部本地保存 |
| 检索 | 款号/关键词/属性检索，目标匹配度 ≥80% 的成功案例 |
| 案例 | 完整穿搭为父案例，单品为可检索子结构 |
| 提示词 | 中文优先；英文只复用已有内容 |
| 更新 | 增量清单 + SHA-256 + 备份 + 事务式安装 + 回滚 |
| 发布 | 隔离候选分支；个人 Windows 验收前不改生产 main |

## 数据安全边界
- 用户数据库、参考图片、API Key、个人配置不进入 Git。
- 更新 allowlist 只允许程序文件；新增运行时依赖必须加入清单和哈希。
- 备份必须先于更新，完整性校验成功后才可继续。
- 写入超时应执行 read-after-write reconciliation，不能谎报失败或错误回滚。
- AI 请求不得把 API Key 转发到重定向目标；远程 API 必须 HTTPS，loopback 开发端点例外。
- 日志不得记录请求正文、凭据或含密钥的异常文本。
- 恢复 ZIP 前拒绝路径穿越、Windows ADS、设备保留名、尾随点/空格、符号链接和大小写冲突。

## 检索与提示词规则
- SKU 精确匹配优先；兼容旧 style_number/product_code。
- 中文材质/颜色别名归一化，如锦纶/尼龙、涤纶/聚酯、真丝/丝绸。
- 服装属性进入结构化字段，不只放自由文本。
- 单品检索仍返回完整穿搭父案例。
- 80% 是筛选目标，不是准确率或生成成功率承诺。
- 感知哈希只做候选缩小，不宣称跨视角语义识别。
- 参考图职责/优先级和控制属性随案例保存；资产编号不会自动改写提示词 @图片引用。
- 模型与平台分开：RunningHub 是平台；WAN 3.0、MiniMax H3、Seedance 2.5 是模型。
- 冲突检测跨模块类型检查，但按服装品类范围隔离；上装拉链约束不能误伤下装。

## 自动更新安全规则
- 默认关闭自动安装，必须用户主动授权。
- 授权后需连续空闲 15 分钟、窗口可见且聚焦，再显示 60 秒倒计时。
- 用户活动、隐藏/失焦、取消操作均应延期或取消。
- 跳过版本需本地持久化，避免反复提示同一版本。
- 更新启动响应丢失时显示“状态未确认”，避免重复启动，不要谎报失败。
- 每次更新前生成完整本地备份并验证下载文件哈希。

## 已知问题与修复经验
| 问题 | 修复/预防 |
|---|---|
| 更新白名单漏运行时依赖，出现 Failed to fetch/旧页面 | manifest 覆盖实际导入模块；CI 根据 manifest 文件列表核对哈希 |
| 智能搜索模板插值转义，显示字面表达式 | 增加模板插值回归检查 |
| SKU 匹配存在但编辑界面无字段 | 编辑表单、检索索引、详情统一加入 SKU |
| 保存失败仍显示成功/内存与服务器不一致 | 事务式保存、失败恢复、超时后读回核对 |
| 批量操作失败污染内存状态 | 保存失败恢复原数据集 |
| ZIP 恢复路径危险 | 解压前做 Windows 路径/符号链接/冲突检查 |
| 旧自动更新 API 默认状态不一致 | 所有路由统一默认未授权，并由 Windows API 测试覆盖 |
| 冲突检测只比较同一模块类型 | 跨模块类型检查，同时按品类范围隔离 |
| manifest 与代码提交不同步 | 串行提交代码、测试、manifest，以 CI 哈希报告核验 |

## 开发与沟通规则
- 用户说“继续”代表持续推进，不要每一步停下来请求确认。
- 常规静态检查、自动化回归由开发侧完成，不让用户充当测试员。
- 只有用户个人 Windows 桌面、真实数据目录或外部界面必须介入时才请求用户。
- 区分代码实现、CI 通过、个人设备验收和正式发布。
- 不用多版本 A/B 试错替代事前反推与风险预检。
- 对话用于指挥和说明；项目事实以 GitHub 代码、测试和本记忆中心为准。


## 2026-11-13 本轮本地 API 安全审计
- 发现：本地服务虽然绑定 127.0.0.1，但原 Handler 未校验 Host；DNS rebinding 场景可利用攻击者域名 Host 将浏览器请求路由到 loopback 服务。原 POST 处理器也未校验 Origin / JSON Content-Type，跨站简单请求可能触发状态写入。
- 修复：所有 GET/POST 先验证 Host 必须为 127.0.0.1 或 localhost，且端口等于当前服务端口；若存在 Origin，则必须为 http loopback 来源且端口相同；JSON POST 必须为 application/json，备份恢复单独走 application/zip。
- 回归：新增恶意 Host、跨来源 JSON 写入和简单表单 content-type 三项测试。最新 CI run 43380232584 的 Windows runner 9 项通过，主验证 96 项运行、95 项通过、1 项环境跳过。
- 兼容性边界：浏览器同源访问和不带 Origin 的本地自动化/CLI 请求仍可用；本机其他进程仍属于本机信任边界，不由 Host/Origin 检查隔离。


## 2026-11-13 更新器事务回滚审计
- 发现：updater.py 原先在恢复每个文件/版本号时使用宽泛 except + pass；若回滚本身失败，用户可能只看到普通更新失败日志，且不知道安装目录处于部分更新状态。
- 修复：逐项收集文件回滚、版本回滚和临时文件清理异常；若任一回滚动作失败，抛出明确的“自动回滚未完整完成”错误，记录失败项和备份目录路径。更新备份目录保留，不自动删除，提示不得删除备份。
- 故障注入：测试安装中途失败后再注入一个回滚失败，验证日志明确、备份目录仍存在、原始文件可从备份恢复。
- Windows 路径大小写：测试比较备份目录 basename 时使用 casefold，避免 Windows runner 的 8.3 路径与日志规范路径差异导致误报。
- 验收：CI run 43380621994 三个 jobs 全通过；97 项主回归中 96 通过、1 项因非 Windows runner 跳过；Windows runner 10 项通过。


## 2026-11-13 完整备份恢复回滚审计
- 发现：restore_full_backup 的回滚阶段原本吞掉 SQLite / JSON / references 恢复异常，并在 finally 删除 rollback_dir；发生二次故障时，恢复前数据副本可能丢失且 UI 仅收到笼统错误。
- 修复：分别收集数据库、JSON、参考图片目录的回滚异常；有任一项失败则 keep_rollback_dir=True，不删除恢复副本，错误消息同时给出 rollback_dir 和恢复前完整 safety ZIP 的位置，明确提示不要删除。
- 测试：保留原有中途 JSON swap 失败后正常回滚测试；新增故障注入测试，确保 JSON swap 和 old.sqlite3 回滚再次失败时，恢复前副本目录保留、参考图片仍处于完整状态、路径写入错误信息。
- CI run 43381205157：3 个 jobs 全成功；主回归 98 项（97 通过、1 个 Linux 环境跳过），Windows Server 2025 10 项通过；manifest 验证 9 个更新文件。


## 2026-11-13 多轮代码侧安全与数据一致性审计
- **扫描路径边界：** 采集器不跟随文件/目录符号链接和 Windows junction；入库再次验证扫描结果必须位于注册来源根目录内。手动重扫使用 force_hash，解决同大小且 mtime 被保留时缓存哈希无法更新的问题。
- **扫描并发：** 自动扫描与手动扫描共用 per-source lock；先拿 Storage operation lease，再拿来源锁，避免同一来源并行扫描导致旧快照后写覆盖新快照。
- **AI 请求输入：** 提示词和图片按扫描时 SHA-256 复核；分析器再次校验实际发送的提示词/图片字节。视频只做哈希/元信息处理，不宣称抽帧。
- **AI 输出原文：** 模型输出中的 prompt_text 不可信；始终以本地原文件解码文本为准。审批入库再次比较原始文件内容，且不 strip 首尾空白。
- **AI 入库溯源：** 审批时重新确认原提示词与每个素材仍存在于对应已扫描来源目录，文件类型和数据库扫描哈希匹配，当前文件 SHA-256 仍一致。图片复制过程中再次哈希，避免验证与复制之间的 TOCTOU 变化。
- **AI 文件事务：** 数据库事务失败时删除本次复制的参考图；清理失败时明确报告文件名。参考图片根目录必须是 HOME 下的真实目录，不接受 symlink/junction 重定向。
- **恢复互斥：** SQLite/JSON/参考图恢复使用 exclusive operation gate；正常操作可并发持有 lease，恢复等待在途操作结束并阻止新操作进入。心跳/关闭路由绕过该 gate，watchdog 在恢复期间暂停空闲退出判断。
- **媒体服务：** /media 只允许 PNG/JPG/JPEG/WEBP/GIF/BMP；只从 canonical HOME/references 目录提供普通文件；拒绝链接并添加 X-Content-Type-Options: nosniff。
- **跨站请求：** 在 Host/Origin/Content-Type 之外检查 Sec-Fetch-Site；拒绝 cross-site / same-site 浏览器请求，允许 same-origin 和用户主动导航 none。
- **AI endpoint：** 拒绝 endpoint query/fragment，避免 URL 查询参数携带凭据；限制 endpoint 长度、API Key 长度和模型名长度。
- **日志：** 应用日志按 1 MiB 轮转并保留 3 份；后台扫描只记 source token 和异常类型；API 日志去掉 query 且不记录异常正文。更新器日志同样轮转，并脱敏安装目录、用户目录、Authorization Bearer/API Key/sk-* 模式。
- **前端：** 导入案例时间字段插入 innerHTML 前转义；设置文案与实际 15 分钟检查及明确授权安装行为一致。
- **CI 证据：** run 43388913191 三个 jobs 全部通过；121 项主回归（120 通过、1 环境跳过），Windows Server 2025 18 项通过，9 个更新文件 SHA-256 校验通过。此证据不代替用户本人 Windows 桌面和真实资料验收。

## 2026-11-13 批量操作选择集的筛选边界
- 风险：案例库/模块库的多选集合跨页面重渲染保存；用户切换筛选后，先前隐藏的记录仍留在选择集合中。批量删除可能因此影响当前不可见的资产。
- 决策：每次按当前可见结果渲染列表时，将选择集合裁剪为当前可见 ID。筛选隐藏的项目自动取消选中，避免不可见资产进入批量操作。
- 回归：Node 行为测试验证可见 ID 保留、隐藏 ID 被清除；前端语法测试同时检查案例与模块两条路径均调用裁剪函数。


## 2026-11-13 组合草稿必须绑定生成时来源快照
- 问题：原 saveDraft() 在保存时重新读取当前基础案例下拉框和模块勾选项。如果用户生成组合后更改了选择，但没有重新生成，最终文本来自旧选择，来源记录却来自新选择，造成可追溯性失真。
- 修复方向：composeNow() 成功生成时冻结基础案例 ID/名称/更新时间及模块 ID/名称/更新时间；saveDraft() 只读取该快照，不再读取当前控件来推断来源。
- 如果生成后手动编辑输出，保留原始来源并标记 passed_then_manually_edited / modified_after_generation=true；手动输入且无生成快照时明确标记 not_generated_by_composer，不伪称预检通过。
- 回归：Node 行为测试覆盖未修改、生成后手动编辑、无来源快照三种路径。


## 2026-11-13 统一所有服务器刷新路径的数据归一化
- 问题：初始 load() 会把旧版字符串 tags 归一化为数组，并清理异常 image/timestamp 类型；但回收站恢复、历史版本恢复、AI 审核入库、生成结果刷新和超时写入协调会直接把 API 返回对象赋给 db，绕过归一化。旧数据可能在下一次 render 时因 tags.map/slice 不是函数而破坏页面交互。
- 修复：提取 normalizeAssetRows()/normalizeAssetData()，让启动加载及所有服务器刷新路径共享同一数据结构边界；无效 payload 会被拒绝，而不是注入 UI。
- 回归：Node 测试覆盖字符串/数组 tags、非法图片路径/时间字段、无效记录过滤及结构错误；静态断言检查所有刷新入口都调用统一函数。


## 2026-11-13 JSON 导入合并边界
- 导入时现有 ID 集合未 trim；若旧资产 ID 带首尾空格，新导入的规范 ID 可能绕过前端去重，最终被存储层拒绝，整批导入回滚。原逻辑也未为 FileReader 设置 error/abort 反馈，且同一文件再次选择可能不触发 change。
- 修复：抽取 mergeImportedAssets()，以 trim 后的 ID 集合跨 cases/modules 与整个导入批次去重；仅接受 string/number ID；先构建新数组，保存前不修改当前数据；保留重复/无效跳过计数。FileReader 增加错误/取消反馈，文件选择后立即重置 input，允许再次选择同一文件。
- 回归：Node 行为测试覆盖旧 ID 空格、已有重复、同批重复、跨类别重复、空 ID、非法 ID 类型、标签/图片字段归一化以及不修改原数组。

# Prompt Atelier — 项目总纲

**定位：** AI 服装视觉资产与提示词智能生产工作台  
**当前阶段：** V1.0 候选开发，尚非正式发布  
**整理依据：** 截至 2026-11-13 已确认的对话需求、项目记忆和候选分支代码。

## 1. 产品目标
建立可持续积累、可检索、可复用的本地知识与生产工作台。核心不是简单收藏提示词，而是把完整成功穿搭、完整提示词、服装单品、参考图片、图片职责、生成约束、模型/平台信息和真实生成结果关联起来。

当前以个人使用为主，未来考虑团队协作。先稳定、后扩展。

## 2. 已确认的核心要求
- 本地优先：案例库、数据库、参考图片、配置和备份默认保存在用户本机。
- AI API + 本地程序：AI 可辅助分析历史素材，但识别结果必须人工审核；不得把推测写成事实或自动标记成功。
- 多来源采集：扫描用户指定本地文件夹，不限定 RunningHub；可采集其他平台或本地完成的穿搭资料。
- 完整案例：一套成功穿搭作为完整案例，关联完整提示词、款号/SKU、素材和单品拆解。
- 智能检索：输入款号、SKU、商品编码或自然语言描述，检索历史成功案例；目标优先展示匹配度 ≥80% 的案例，并显示命中理由和差异。80% 是筛选目标，不是正确率保证。
- 单品检索：可从完整穿搭中检索单件上衣、裤子、鞋履或配饰，同时保留父案例上下文。
- 提示词组合：案例与模块组合，保留参考图职责、优先级、服装结构和硬约束；中文优先，支持已有英文版本。
- 稳定更新：用户希望授权后自动同步；更新必须校验、备份、保留用户数据并可失败回滚。
- 可追溯：重要编辑、生成结果和资产变更有版本记录，可比较和恢复。

## 3. 核心工作流
1. 指定本地素材文件夹并扫描候选资料。
2. 识别提示词、款号、服装图片及来源；不能假设当前版本已支持视频自动抽帧。
3. AI 分析整套穿搭：单品类别、名称、颜色、材质、廓形、合体度、细节、参考图角色和有证据支持的穿搭关系。
4. 用户审核修正并确认；只有明确验证成功的案例才进入成功案例优先集合。
5. 保存完整案例、提示词、来源路径、哈希和分析记录。
6. 按款号、关键词、属性、单品或图片线索检索。
7. 组合案例与模块，检查模型适配、品类范围和硬约束冲突。
8. 生成后反馈成功/失败，保留版本并积累评估数据。

## 4. 功能范围
### 案例与资产
- 案例、模块、提示词正文及可选英文版本。
- SKU/款号/商品编码；品类、款式、廓形、合体度、面料组成、材质、颜色、表面质感、工艺、走线、结构细节和生成约束。
- 完整穿搭最多 12 件单品的结构化拆解及有证据支持的单品关系。
- 参考图片用途角色、权威优先级、控制属性和观察说明。
- 批量标签/状态管理；删除前确认，保留可恢复历史。

### 历史素材采集与审核
- 指定文件夹扫描，不限定平台。
- 保存原始素材路径、类型、SHA-256、模型、分析 ID 和导入时间。
- 图片角色建议：overall/front/back/detail/fabric/label/scene/other/unknown。
- AI 分类只是建议；缺失、异常或不确定信息必须保留待确认状态。

### 智能检索
- SKU 精确检索，兼容旧 style_number 和 product_code 字段。
- 中文服装术语、材质/颜色别名归一化及结构化属性检索。
- 单品级命中仍返回完整穿搭父案例。
- 显示分数、命中属性、差异和案例状态。
- 当前感知哈希只作近重复/视觉结构候选缩小，不是语义服装识别；跨视角和背景变化会影响准确性。
- 检索反馈用于评估，不得静默改变排序权重。

### 提示词工作区
- 案例 + 模块组合，支持已有中英文内容。
- 模块类型与适用品类范围分别管理。
- 检查拉链状态、袖型、帽子结构等硬约束；跨模块类型也要检查，但不同服装品类的独立属性不能误判冲突。
- 模型指导为通用经验，不得伪称官方参数。已覆盖 WAN 3.0、MiniMax H3、Seedance 2.5；RunningHub 是平台，不是模型。
- 参考图编号不会自动改写原提示词中的 @图片编号，必须提示人工映射。

### 数据安全与更新
- 本地 SQLite 与程序文件分离。
- 完整 ZIP 备份包含一致性 SQLite 快照、JSON 导出和参考图片，并校验每个成员 SHA-256。
- 更新前先完成可验证备份；备份失败则不得开始替换。
- 只更新清单列出的程序文件；不得覆盖数据库、图片、密钥或个人配置。
- 下载校验、事务式安装、失败回滚、临时文件清理和真实安装版本确认。
- 自动更新必须用户明确授权，可取消；用户活动、窗口隐藏或失焦时应延期。

## 5. 交互与设计偏好
- 中文优先；现代化、科技感但不花哨，适度透视感。
- 保存、删除、导入和更新必须真实反馈，不能假成功。
- 关键操作具备防重复提交、等待状态、超时与失败恢复。
- 用户不希望反复 A/B 试错或充当常规测试员；开发侧先反推、检查和回归。
- 只有必须访问用户个人 Windows 桌面、真实数据目录或外部界面时才请求介入，并一次说清步骤和原因。

## 6. 非目标与边界
- 当前不是多人实时协作系统；团队协作属于未来方向。
- 不默认把本地参考图或完整数据库上传云端。
- 不把感知哈希包装成语义视觉理解。
- 不编造英文翻译、未见服装属性、成功结果或模型官方参数。
- 未完成验收不得把候选分支合并到生产 main。

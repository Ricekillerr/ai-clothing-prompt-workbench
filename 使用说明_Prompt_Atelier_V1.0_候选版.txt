Prompt Atelier｜AI 服装提示词资产工作台
V1.0 候选版使用说明
适用分支：release/v0.6.5-stabilization

一、工作台定位
Prompt Atelier 用来沉淀已经验证过的 AI 服装搭配、人物换装和人物换景提示词。你可以按款号、服装描述、面料、颜色、版型、细节和模型检索历史案例，再以完整成功案例为基础组合可复用模块。

本工作台不是自动生成结果的保证工具。匹配分数是本地可解释的属性匹配结果，不代表模型生成成功概率。

二、启动与本地数据
1. 将程序文件放在同一个文件夹。
2. 双击“启动AI服装提示词工作台.bat”。
3. 工作台会在浏览器打开本机地址 http://127.0.0.1:8765。
4. 用户数据默认保存在 Windows 用户目录下的 AI_Prompt_Asset_Workbench 文件夹中。

本地数据包括 SQLite 案例数据库、JSON 导出、references 参考图片、完整备份、更新前备份和必要的本地配置。程序更新只替换更新清单中的程序文件，不应覆盖用户数据库、参考图片或本地配置。

不要把 AI_Prompt_Asset_Workbench 文件夹当作程序缓存删除。

三、建立成功案例
建议每个完整成功案例至少记录：
- 案例名称与商品款号 / SKU
- 服装品类、款式、廓形、松量
- 面料组成、表面质感、颜色
- 结构细节、工艺、生成约束
- 适用模型与完整提示词
- 正面、反面、细节、面料等参考图
- 实际生成效果与失败风险备注

一套穿搭可以在“整套穿搭拆解”中按单品逐行记录。只填写明确可见或已知的信息；不确定的属性留空，不要把 AI 推测当成已验证事实。

参考图可以设置用途、主次优先级及控制属性：
- primary：主参考，决定对应属性的主要依据
- secondary：次参考，用于补充或细化
- supporting：辅助参考，只提供局部补充
参考图序号是工作台内部资产索引，不会自动重写原始提示词中的 @图片编号；组合提示词前请人工核对 @图片编号与实际输入顺序。

四、历史素材采集与 AI 分析
1. 打开“数据与备份”中的“历史案例自动采集”。
2. 输入本机历史素材文件夹的完整路径并添加。
3. 点击“立即扫描”，或开启自动监控。
4. 查看待审核文件；文件关联建议仅供参考。
5. 按同一套穿搭选择提示词与 1–8 张相关图片。
6. 运行 AI 分析，检查图片角色、单品拆解、材质、颜色、细节和风险提示。
7. 只有人工确认后，分析结果才会进入正式案例库。

扫描过程只读取原始素材，不移动、重命名或删除源文件。视频目前只登记文件信息，不做抽帧或视频内容理解。

隐私提醒：
- API Key 只随本次 AI 分析请求传递，不保存到工作台数据库。
- 选择 AI 分析后，提示词文本与所选图片会发送到你填写的 AI 服务端点。请确认服务商可信，并确认素材可用于该服务。
- 非本机 AI API 地址必须使用 HTTPS。
- 不要把 API Key 写进提示词、案例备注或截图。

五、智能案例检索
- 可输入商品款号、SKU 或自然语言服装描述。
- 默认只检索标记为“已验证成功”的案例。
- 默认阈值为 80%；低于阈值的候选不会显示。
- 检索会显示命中和缺失的属性，并检测明确的颜色、材质冲突。
- 精确款号匹配优先。
- 可以对结果标记“匹配有帮助”或“不符合需求”；反馈仅用于评估，不会未经验证自动改变排序权重。

匹配分数是本地属性覆盖与相似度评分，不是 AI 置信度，也不代表视频模型生成成功率。旧案例若缺少结构化字段，可能无法达到 80%。

图片检索使用浏览器本地感知哈希做粗略视觉初筛，图片不会上传。它适合寻找近似图或重复素材，不等同于识别同一款衣服，也不能代替人工核对。

六、智能组合器
1. 选择一个完整成功案例作为基础提示词。
2. 勾选需要追加的提示词模块。
3. 按需选择附加结构化单品拆解、参考图优先级说明、已保存的英文版本和模型通用适配提醒。
4. 检查组合冲突与输出内容。
5. 复制提示词，或另存为待验证案例。

模型提示：
- WAN 3.0：重点明确源视频人物、动作、机位、背景与光影锁定范围，以及局部服装编辑边界。
- MiniMax H3：按时间顺序描述动作、主体和镜头变化，避免同一时间段堆叠互相矛盾的动作。
- Seedance 2.5：明确人物、服装、场景参考图各自职责，并保持跨帧一致性。
- RunningHub 是运行平台，不是具体视频模型；请先确认平台中实际调用的模型。
以上是工作台通用创作建议，不是厂商官方参数或生成保证。

七、记录生成结果
在案例详情中可以标记本次生成“成功”或“失败”，并填写可选备注。
- 标记成功：案例状态变为“已验证成功”，默认可被智能检索。
- 标记失败：案例状态变为“失败案例”，默认不会作为成功案例推荐，但仍可在人工复核时查看。
- 每次记录会保留修改前的历史版本，并写入本地成功 / 失败统计。

请根据真实生成结果记录，不要为了提高匹配数量把失败案例标成成功。

八、历史版本与恢复
案例编辑、删除和生成结果变更会保留历史版本。可查看历史版本、与当前提示词对照，并按需恢复。

九、完整备份与恢复
建议在批量导入、重大编辑和程序更新前创建完整 ZIP 备份。
完整备份包括：
- SQLite 数据库快照
- JSON 数据导出
- references 目录中的参考图片
- 每个备份文件的 SHA-256 清单

恢复前，工作台会验证 ZIP 格式、文件清单、路径安全、文件 SHA-256、SQLite 完整性以及数据库与 JSON 内容一致性，并先创建当前数据的安全备份。

重要：SHA-256 可以发现文件损坏或内容不一致，但不是数字签名，不能证明备份来自谁。只恢复你信任来源的完整备份。不要解压后手动覆盖数据库文件。

十、自动更新
自动更新授权默认关闭。
1. 打开“数据与备份”中的“自动更新授权”。
2. 点击“自动更新：未授权”按钮，启用本地授权。
3. 工作台启动时及运行期间每 15 分钟检查一次更新。
4. 授权后，发现新版本会等待连续空闲 15 分钟，再显示 60 秒倒计时。
5. 倒计时期间任何鼠标、键盘、触摸或窗口切换操作都会延期。
6. 可以取消当前版本的自动安装；同一版本不会反复安排，出现更新版本后再重新判断。
7. 每次安装前会自动创建完整本地备份，并校验更新文件 SHA-256。

关闭授权后，工作台仍可检查更新，但不会自动安装。也可以随时使用“立即一键更新”。

如果更新请求时连接中断，界面可能提示“更新状态未确认”。请先等待工作台关闭并重启，不要连续重复启动更新。

十一、常见问题
1. 浏览器无法打开：
   - 确认启动脚本没有被关闭。
   - 确认本机 8765 端口未被其他程序占用。
   - 只在本机浏览器打开 http://127.0.0.1:8765，不要将本地服务暴露到公网。

2. 案例没有被检索出来：
   - 检查案例是否标记为“已验证成功”。
   - 补充 SKU、品类、材质、颜色、版型和结构细节。
   - 检查检索描述是否与案例属性冲突。
   - 80% 是属性匹配阈值，不是模型生成置信度。

3. 自动更新没有安装：
   - 检查自动更新授权是否开启。
   - 确认工作台能连接 GitHub。
   - 检查是否取消过当前版本的自动安装。
   - 授权更新只会在空闲条件满足后安装。

4. 不要随意删除：
   - AI_Prompt_Asset_Workbench
   - references
   - backups
   - _update_backup
   这些位置可能包含你的数据库、图片或更新恢复文件。

十二、当前已知限制
- 视频尚不支持抽帧理解。
- 图片感知哈希只是粗略视觉初筛，不是同款语义识别。
- 英文提示词需人工提供与核对，工作台不会自动翻译。
- 参考图内部序号不会自动改写原始 @图片编号。
- AI 分析和匹配结果都需要人工复核。
- 自动化 Windows CI 通过不等于你的个人电脑环境已经验收。

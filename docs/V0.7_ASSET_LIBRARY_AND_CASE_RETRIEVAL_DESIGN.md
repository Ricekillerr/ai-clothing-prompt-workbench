# V0.7 Asset Library and Case Retrieval — Technical Design

Status: design baseline only. No database migration is authorized by this document. Implementation must preserve the current SQLite schema and legacy JSON import behavior until migration tests exist.

## Current repository baseline
The current storage layer uses:
- `assets(id, kind, payload_json, created_at, updated_at)` for case/module records.
- `attachments` for linked files, including relative path, role, media type, and SHA-256.
- `scan_sources` and `ingest_files` for monitored folders and review status.
- `ai_analyses` for review/approval/rejection of AI-assisted extraction.
- `metadata.schema_version` for schema tracking.

The current case matcher ranks textual attributes and can return a numeric score. The UI must not describe that score as an AI confidence probability.

## V0.7 user outcome
A complete successful outfit case should be reusable as a single source record. A user can search by SKU or natural-language description and retrieve relevant verified cases, then inspect the complete prompt and its linked reference assets.

## Canonical case structure
Keep the existing JSON payload extensible. New optional fields:
- `sku`: exact user-provided garment/style identifier.
- `case_status`: `verified_success`, `pending_review`, `failed`, or `archived`.
- `outfit_items[]`: one entry per garment/accessory with `item_id`, `category`, `subcategory`, `name`, `material`, `color`, `silhouette`, `fit`, and `details[]`.
- `outfit_relations[]`: explicit relationships such as outer-layer-over-inner-layer; do not infer hidden garment layering from a single image.
- `model_context`: generator/model/version and relevant input mode.
- `reference_roles[]`: image/file ID, role, priority, and what visual property it governs.
- `prompt_versions[]`: immutable prompt text snapshots with timestamp and parent version.
- `provenance`: source prompt, source asset IDs, extraction method, human reviewer, and verification timestamp.
- `match_exclusions[]`: known mismatches or failure conditions learned from a case.

Existing records without these fields remain valid and are treated as legacy/unknown, not silently assigned fabricated values.

## Retrieval order
1. Exact SKU match is a deterministic shortcut, but only when SKU is present and unambiguous.
2. Apply hard filters first: garment category, required model compatibility, case status, and explicit must-have constraints.
3. Score soft attributes: silhouette/fit, material/texture, color, construction details, scene/context.
4. Return matched attributes, missing attributes, and conflicting attributes separately.
5. Default verified-success search excludes pending, failed, and archived records unless the user explicitly requests them.

A similarity score is a ranking aid, not an 80% probability that the result is correct. Thresholds must be evaluated against a curated labelled test set before being described as match quality.

## Image and attachment rules
- Keep original image files in the existing user data directory, outside replaceable application files.
- Use stable attachment IDs/relative paths; do not rely on display names alone.
- Preserve SHA-256 and reference role.
- Never replace an original image during deduplication. Duplicate detection may suggest a link to an existing asset for human confirmation.
- Deleting a case must not delete a shared image unless reference counts prove it is unreferenced and the user confirms the cleanup.

## Migration strategy
- Bump schema version only when a concrete migration is implemented.
- Migrations must be transactional, idempotent, and tested on a copied database.
- Take a verified backup before migration.
- Keep old payload fields and unknown keys intact.
- Verify record counts, IDs, attachment references, and image hashes before accepting migration.
- Roll back fully on any validation error.

## V0.7 acceptance
- Create/edit/archive/restore a full outfit case.
- Attach multiple reference images with explicit roles.
- Store and reopen complete prompt text without truncation.
- Search exact SKU and natural-language descriptions.
- Show why each result matched and what is missing/conflicting.
- Ensure pending/failed cases do not pollute verified-success results.
- Test duplicates, missing images, renamed folders, repeated imports, and migration rollback.
- No user-data files are modified by an application update.

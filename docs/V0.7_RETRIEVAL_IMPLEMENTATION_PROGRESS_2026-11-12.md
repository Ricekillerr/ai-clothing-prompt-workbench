# V0.7 Retrieval Implementation Progress — 2026-11-12

## Implemented on the isolated stabilization branch
The current legacy branch's `case_matcher.py` now exposes `explain_case_match(case, query)`.

For each recognized query dimension, the function returns:
- attribute key and Chinese display label;
- recognized query terms;
- terms found in the case;
- terms not found in the case;
- deterministic coverage ratio.

`rank_case_matches()` includes this explanation as an additional `attribute_details` field. Existing fields (`case`, `score`, `match_percent`, and `reasons`) remain unchanged for backward compatibility.

## Scope and limitations
- No SQLite schema change was made.
- No existing user records or images are modified.
- The coverage value is a deterministic lexical attribute coverage score, not an AI confidence probability.
- Missing terms mean the case does not explicitly contain recognized query terms in the corresponding stored fields; they are not proof that the garment physically lacks the feature.
- Explicit contradiction detection (for example, a black query against a red-only case) is not implemented yet.
- The implementation is on the legacy stabilization snapshot and must be reconciled with the exact V0.6.5 candidate source before it can be considered part of a release.

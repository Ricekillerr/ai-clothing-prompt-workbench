# Prompt Atelier 轻量审查门禁

**版本：** 1.0（2026-11-16）

**适用分支：** `release/v0.6.5-stabilization` 及后续开发分支

**当前边界：** 只读路径审查与条件安全回归，不部署自动构建者，不调用模型，不自动合并或发布。

## 1. 目的

借鉴 GitHub Agentic Workflows 的“有限返修、分轴审查、信任边界、人工合并”思想，但不把完整 Issue→PR→自动返修闭环直接接入项目。当前目标是提高研发审查的一致性，同时保护本地资料、凭据、费用和发布分支。

本机制不能替代正常浏览器 GUI、真实 SQLite/参考图片、真实模型、杀毒软件、网络权限或长时间运行验收。

## 2. 当前实际启用内容

### 只读路径分析

`.github/workflows/review-gate.yml` 调用 `tools/review_gate.py`：

- 只读取 Git 变更路径，不读取用户数据库或参考图片内容。
- 检测到疑似真实数据库、参考图目录、个人配置或凭据文件时返回非零，阻止该检查通过。
- 触及信任边界时输出 `security_required=yes`，触发条件安全回归。
- 结果写入 Actions step summary；不自动评论 PR、添加标签、推送、批准、合并或 Release。
- 工作流权限固定为 `contents: read`，不使用 `pull_request_target`，不需要模型 Key 或 `CI_TRIGGER_TOKEN`。

### 四维审查

每个 PR 按以下维度保留独立结论，不能用某一维度通过抵消另一维度失败：

1. **规范：** 项目结构、编码、LF/CRLF、测试和文档约定。
2. **需求：** 改动与需求、验收条件一一对应，没有夹带无关范围。
3. **质量：** 无重复实现、僵尸按钮、静默失败或无法验证的完成声明。
4. **影响范围：** 启动、关闭、检索、备份、恢复、更新和旧数据兼容性。

所有问题应尽量提供 `path:line` 证据。AI 意见只能作为审查建议，维护者仍是唯一合并门禁。

## 3. 路径触发的高风险审查

| 路径或类型 | 追加审查重点 |
| --- | --- |
| `.github/workflows/*`、`tools/review_gate.py` | 权限、供应链、事件触发、 secrets 暴露、自动写入 |
| `ai_analyzer.py`、`collector.py` | HTTPS、API Key、重定向、输入哈希、反序列化、来源边界 |
| `ai_prompt_workbench.py`、`index.html` | 本地 API、Host/Origin、浏览器交互、网络安全、生命周期 |
| `storage.py` | SQLite、文件路径、备份恢复、链接/联接、SHA-256 |
| `updater.py`、更新与同步脚本 | 更新事务、程序替换、回滚、临时文件、命令执行 |
| `.bat`、`.cmd`、`.ps1`、`.sh` | Shell 注入、编码、换行、进程和路径处理 |
| 依赖清单 | 来源、版本、锁文件和供应链影响 |

条件安全回归通过只说明自动化证据通过，不表示人工安全审查或实机验收已经完成。

## 4. 私有资料 fail-closed

以下路径或文件不得进入提交：

- 真实 SQLite / DB 文件；
- `DataHome/`、`references/`、`reference_images/`、`user_data/`、`Backups/`、`_backup/` 中的本地资料；
- `.env`、私钥、证书和个人配置文件；
- API Key、密码、令牌或其他凭据。

路径检查是第一道防线，不替代内容级秘密扫描。仓库未启用 GitHub Advanced Security，因此不得宣称“秘密扫描已通过”。发现真实资料时应从提交中移除并评估凭据轮换，不得仅修改文件名绕过门禁。

## 5. 两轮返修上限

- 当前阶段不启用自动构建者，所有修复仍由开发者或维护者执行。
- 若未来另行批准自动或半自动返修，最多允许 **2 轮返修**；第 **3 次审查**仍有发现时停止后续自动运行并转人工。
- 返修轮次应根据已有审查记录计算，不能由新的输入参数或重写提示词重置。
- 当前 PR 模板要求填写轮次并由维护者执行；**本轮没有声称已在 Runner 中自动统计评论或审查轮次**。
- 不通过空提交、重复触发工作流或 `CI_TRIGGER_TOKEN` 绕过上限。

## 6. 预算、网络与版本边界

- 当前工作流不调用 AI 模型，因此没有 AI credits 消耗；主要成本是普通 CI 运行时间。
- 两个 job 均设置 `timeout-minutes: 10`，仅高风险路径触发安全回归。
- Python 固定为 3.12；Actions 版本沿用仓库现有 `actions/checkout@v4` 与 `actions/setup-python@v5` 约定，不宣称已固定到完整提交 SHA。
- 不安装 `gh aw`，不引入第三方 skills，不开放额外出站网络，不配置真实模型凭据。

## 7. 未来升级门禁

只有在只读审查稳定、V1.0 实机门禁完成并获得用户单独确认后，才可评估 Issue→PR 自动构建者。届时必须：

- 固定到明确 Release tag 和来源 commit SHA，记录许可证与更新方式；
- 设置单次/每日 AI 额度、最大轮次和超时；
- 默认关闭额外网络，逐个声明必须访问的主机；
- 先用合成数据和小型文档/测试 Issue 试点；
- 保持评论式审查、人工合并、禁止自动 Release；
- 不上传真实 SQLite、参考图片、个人配置或 API Key。

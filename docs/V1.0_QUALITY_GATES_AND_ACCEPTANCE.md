# Prompt Atelier V1.0 — Quality Gates and Acceptance Matrix

This document is the canonical acceptance checklist for the V1.0 release. A check is complete only when its evidence is attached to a reproducible test run or a Windows acceptance report. The final V0.6.5 candidate automation evidence is: cloud Linux, 176 tests with 174 passed and two environment skips in 12.674 seconds; Windows Python 3.13, 176 tests with 172 passed and four permission/environment skips in 24.234 seconds; portable Windows Python 3.12.10, 176 tests with 172 passed and four skips in 23.820 seconds. The new Windows short-path regression executed and passed in both local Windows runtimes. GitHub Actions run [43572935991](https://github.com/Ricekillerr/ai-clothing-prompt-workbench/actions/runs/43572935991) (`7527bd242f6868eff80d461ba88e7795946031b0`) passed Linux validation, the full Windows job and the release source/channel gate in 47 seconds; run [43572734163](https://github.com/Ricekillerr/ai-clothing-prompt-workbench/actions/runs/43572734163) previously proved the restored unified 175-test workflow green. Detailed logs remain login-gated; the CI evidence here uses the public run summaries plus complete local logs. These automated results do not replace manual desktop interaction, real-data acceptance or real-model evaluation.

## Gate 6 — Explainable retrieval
- [x] Explicit garment-category conflicts are rejected before soft similarity; unstructured full-outfit cases remain eligible when contents are not itemized. Structured multi-item outfits are scored one garment at a time.
- [x] Results expose matched/mismatched attribute details in the current candidate UI.
- [x] Score weights and missing-attribute behavior documented: category 0.25, material 0.20, color 0.15, details 0.20, context 0.20; only query-present dimensions are renormalized; a requested but missing attribute receives zero coverage; unrequested dimensions do not reduce the score; residual free-description terms use an additional 0.10 weight; exact SKU match bypasses attribute scoring.
- [x] Threshold behavior has a curated regression fixture for a garment item retrieved from a complete outfit; 80% threshold and explanation reasons are asserted.
- [x] Multi-item outfit search does not mix sibling/parent garment attributes; a black nylon vest plus red leather trousers cannot falsely match a black leather vest. Results expose the matched item label while returning the complete outfit parent case.
- [x] A curated 14-case / 14-query labelled benchmark asserts precision@1 ≥ 90%, recall@5 ≥ 90%, and precision@5 ≥ 50%, covering upperwear, trousers, footwear, accessories, skirts, and hard negatives.
- [x] Failed and unverified near-duplicate cases are excluded by default in the labelled retrieval regression.
- [ ] Larger manually labelled production-library evaluation and precision@k/recall@k remain open.
- [x] Visual-search regression covers a 63-bit non-DC perceptual hash, brightness-shift stability, exact hash-length validation, oversized-image rejection, verified-case filtering, per-case best-image deduplication, unreadable media, a 12/63 Hamming-distance cutoff, a 500-image cap with visible truncation, and stale-request isolation.
- [ ] Real-library visual retrieval still needs same-SKU/different-angle, background-change, and similar-looking/different-SKU evaluation on the user's actual image library.

## Release decision
V1.0 may be marked stable only when Gates 0–8 are complete, all critical/high severity issues are closed, the Windows acceptance report is attached, and backup/restore plus update/rollback have been demonstrated on a clean test copy and the user's existing data. A passing non-Windows test suite or isolated Windows CI is not a substitute for the user's own Windows acceptance.
